# 雀魂大会 参加者統計アプリ 設計書

日付: 2026-10-04

## 目的

雀魂の大会管理アプリからエクスポートした「シーズン順位統計」CSVを取り込み、主催者自身の大会について参加者の参加履歴・参加回数・対局数などを自動集計する。

- 想定ユーザー: 大会主催者（各自が自分の大会データを使う）
- 最初の利用者のデータ: 深海杯 第1〜8回（トーナメント）、五光、夏宵、五光弐、夏宵2
- サーバーなし。データは各利用者のブラウザ内に保存する

## 入力データ

雀魂「シーズン順位統計」CSV。トーナメント形式の大会も同じ形式で出力される。

```
順位,プレイヤーID,プレイヤー名,対局数,累計打点,表示得点,備考,点数修正,
1,900000001,プレイヤー01,33,298.6,298.6,,0.0
```

- ファイル名: `シーズン順位統計-大会708677.csv`（`大会(\d+)` を雀魂大会IDとして抽出）
- CSV内に大会名は含まれない
- 文字コード: UTF-8 / Shift_JIS の両方に対応する（BOM有無も許容）
- 必須列: 順位, プレイヤーID, プレイヤー名, 対局数, 累計打点。欠けていれば取り込み不可

## データモデル（IndexedDB / Dexie.js）

- **Series**: `id`, `name`
- **Tournament**: `id`, `seriesId`, `label`（回の表記。自由入力。例「第3回」「弐」）, `startDate`・`endDate`（開催期間 YYYY-MM-DD。大会は複数日にまたがることが多い。1日開催なら両方同じ日。並び順は `startDate` を使用）, `mahjongSoulId`（雀魂大会ID。任意）, `importedAt`
- **Result**: `id`, `tournamentId`, `playerId`, `playerName`（その大会時点の名前）, `rank`, `games`, `totalPoints`
- **Player** は保存しない。Result から導出する。表示名は最新（開始日が最も新しい）大会の名前

## 集計の定義

- **参加**: その大会のCSVに行がある
- **参加大会数**: 参加した大会の数（シリーズ絞り込み時はそのシリーズ内の数）
- **通算対局数 / 通算打点**: 対象大会の `games` / `totalPoints` の合計
- **新規**: 全大会（全シリーズ）を開始日順に並べて、その大会が初登場
- **リピーター**: 新規でない参加者
- **継続率**: 同シリーズの直前の回の参加者のうち、今回も参加した人の割合。シリーズ初回は「—」
- **皆勤者**: シリーズの全回に参加した人
- **ユニーク参加人数**: シリーズ内の重複なし参加者数。**のべ参加人数**: 各回の参加人数の合計

開始日が同じ大会が複数ある場合は取り込み順で並べる。

## 画面

ヘッダーにタブ5つ。スマホ表示に対応する。

1. **プレイヤー一覧**
   - 列: 名前 / 参加大会数 / 通算対局数 / 通算打点 / 最終参加大会
   - 列クリックで並び替え、名前・IDで検索、シリーズで絞り込み
   - 行クリックでプレイヤー詳細へ
2. **プレイヤー詳細**
   - プレイヤー名・ID
   - 参加大会の一覧（シリーズ・回・開催期間・順位・対局数・打点）を開始日順
   - シリーズ別参加回数（例: 深海杯 6/8回）
3. **大会集計**
   - 大会ごとの行: シリーズ・回 / 開催期間（例 10/1〜10/14） / 参加人数 / 新規 / リピーター / 継続率
   - 行クリックでその大会の順位表
4. **シリーズ集計**
   - シリーズごと: 開催回数 / のべ参加人数 / ユニーク参加人数
   - 皆勤者リスト、シリーズ内の参加回数ランキング、通算対局数ランキング、通算打点ランキング
5. **データ管理**
   - CSV取り込み
   - 大会の編集（シリーズ・回・開催期間）と削除（削除は確認ダイアログあり）
   - シリーズ名の変更
   - バックアップ書き出し / 読み込み（JSON）

### CSV取り込みの流れ

1. CSVをドラッグ&ドロップまたは選択（複数可）
2. ファイル名から雀魂大会IDを抽出
3. 1ファイルずつ、シリーズ（既存から選択 or 新規作成）・回・開催期間（開始日・終了日。終了日は省略で開始日と同じ）を入力
4. プレビュー（人数・上位5名）を確認して保存
5. 同じ雀魂大会IDが既にあれば「上書きしますか？」と確認。上書き時はその大会の Result を差し替える

### 画像出力

プレイヤー一覧・大会集計・シリーズ集計に「画像で保存」ボタン。表示中の表をPNGで保存する。出力件数（上位N件）を指定できる。画像にはタイトル（例「深海杯 参加回数ランキング」）を入れる。

## エラー処理

- 必須列不足・形式違いのCSV: 取り込み前に「このファイルは対応形式ではありません」と表示し、そのファイルは取り込まない
- 数値として読めない行: スキップし、プレビューに「○行スキップ」と表示
- バックアップ読み込み: 「現在のデータをすべて置き換えます」と確認。JSONの形式が不正なら中止してデータは変更しない

## 技術構成

- Vite + React + TypeScript
- Dexie.js（IndexedDB）
- PapaParse（CSV解析）+ TextDecoder による文字コード判定（UTF-8で不正バイトがあれば Shift_JIS で再デコード）
- html-to-image（PNG出力）
- React Router（HashRouter。GitHub Pages で動作させるため）

### ディレクトリ

```
src/

  lib/stats.ts      集計ロジック（純粋関数）

  db/               Dexie定義と読み書き

```

## テスト

- `lib/csv`・`lib/stats`・`lib/backup` を Vitest で単体テスト
- 実データ（大会708677のCSV）をテスト用フィクスチャとして使う
- 画面はブラウザで実操作して確認

## 公開

GitHub Pages に静的サイトとしてデプロイ。他の主催者はURLを開くだけで使える。

## 対象外（今回はやらない）

- 平均順位・最高順位などの成績系統計
- 名前変更履歴の表示
- CSV出力
- 複数人でのデータ共有・サーバー保存

## 追加仕様: 1大会に複数CSV（パート）（2026-10-07）

### 背景

夏宵2 のように、1つの大会が複数の雀魂大会（CSV）に分かれていることがある（夏宵2-1 / 2-2 / 2-3）。依頼者が欲しい「夏宵2の参加人数」は、どれか1つにでも出た人を1人と数えた数（実データで 1474人）。

### データモデル

- **Part**（新規）: `id`, `tournamentId`, `name`（パート名。ファイル名から初期値を作り、編集できる）, `mahjongSoulId`（雀魂大会ID。ファイル名から抽出、不明なら null）, `importedAt`
- **Tournament**: `mahjongSoulId` を削除（Part へ移動）
- **Result**: `partId` を追加（`tournamentId` は残す）
- 既存データ（DB v1・バックアップ v1）は、大会ごとに Part を1つ（名前「パート1」）作って移行する。大会IDは Part に移す

### 集計の定義（大会単位）

- 1大会での1人の成績 = 全パートの合算（対局数・打点は合計、順位はパートごとに保持）
- 参加人数・新規・リピーター・継続率・皆勤・参加大会数: 大会の**どれかのパートに出た人を1人**として数える
- パートの並び順: パート名の自然順（2-1, 2-2, 2-10）→ 取り込み順

### 画面

- **取り込み**: CSVごとに「取り込み先」= 新しい大会 or 既存の大会 を選ぶ。新しい大会のときだけシリーズ・回・開催期間を入力。パート名はファイル名から自動入力（編集可）。直前に保存した大会が、続くファイルの取り込み先の初期値になる。同じ雀魂大会IDのパートが既にあれば、そのパートの上書きになる（確認あり）
- **大会詳細**: パートが複数あれば「合算」タブ（打点合計順、パート別順位を表示）と各パートの順位表タブ。1つなら従来どおりの順位表
- **プレイヤー詳細**: 大会ごとに1行。順位はパートが1つなら数字、複数なら「2-1: 5位 / 2-3: 12位」
- **データ管理**: 大会の下にパート一覧（人数・大会ID）。パート単位で名前変更・削除。最後のパートを消すと大会も消える
